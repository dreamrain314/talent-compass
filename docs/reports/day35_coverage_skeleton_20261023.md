## 二、关键设计决策（逐条对预注册，含一处刻意保守）

1. **斜杠枚举归并**（§2.1）：括号/斜杠实例清单 → 单个上位要求，命中其一即满足（v=max 天然实现）；「同时具备」并列拆分 mock 未见，保守不拆。
2. **权重来自 JD**（§2.1）：含「优先」→ 加分项 0.5，否则必要项 1.0；学历/年限条目不入要求集。
3. **长 head 不做字面命中（刻意保守，本报告最重要的一条）**：head 归一后 >6 字不参与字面检测——n-gram 滑窗会把「交付」「质量」等通用词误判成支持，违反 §2.3「仅相关不计成立」。长 head 的成立通道只有：括号/斜杠**实例**命中（mock JD 的具体技能都在实例里）或**已核验等价表**命中。
4. **等价表达唯一入口 = 人工核验表**（§2.3）：`data/jobs/equivalence_table.json`（暂不存在，种子=alias_patches 4 对）。无表时，同义改写（嵌入式开发↔"边缘计算网关"）**如实报未证实**——这是设计而非缺陷：宁可显示"哪里仍不知道"，不制造碰词分。Day 6-7 离线裁决（LLM 提议→人工核验→版本化入表）是唯一填充通道。
5. **CE 只重排不成立**（§2.4）：CE 分记录在证据行（相关性信号），成立判定走规则+核验表；CE 高分不改变 relevant_only 的 0 分。
6. **v=max + 矛盾优先**（§2.3）：同分时 contradiction 标记优先于 relevant_only 浮出（不被高相似度覆盖）。
7. **query 侧编码修复**（Day1-2 问题 3 实锤落地）：新引擎 query 走 fastembed `query_embed`（不可用回退官方 bge 指令前缀），passage 侧维持 EvidenceIndex 现状。

**读法（开发观察，非验收结论）**：

1. **总耗时 2191s（36.5 min）跑 ~12300 CE 对 ≈ 0.18s/对**（按员工批 ~30 对/predict）——这是 §四-6 延迟实测的第一笔；验收规模（新采岗位 × 50 人）的成本核算以此为准。
2. **排名两段分化 = 等价表空置的预期形态**：实例词面能命中的（B03/B01/B10/B02）金标进 Top-6；依赖同义改写的（B06 嵌入式↔边缘计算网关、B07 结构设计↔工业大数据、B08/B09 HR 族）沉到 22-47 名。
3. **B07 是最干净的病理解剖**：金标 coverage=0.0，全员均值却 0.2022——CAD/SolidWorks/项目管理等实例词满池都是（都能字面成立），金标的"工业大数据平台/Tableau"是改写（全部如实报未证实）。**这不是引擎失明，是等价表为空**——Day 6-7 人工核验填表是该杠杆的唯一合法解，填表前禁止拿 coverage 分与旧公式比大小。
4. B02 金标 coverage=0.0 仍排第 3：B/P 基座（20 分）+ 无人能字面命中（全员均值 0.0）——语义层召回+CE 排序在无字面信号时托底，与"覆盖分不该独自定生死"的骨架意图一致。

## 五、CE 契约坑（记录防再踩）

本版 sentence-transformers 的 `CrossEncoder.__call__(list[tuple])` 走不通
（`'list' object has no attribute 'get'`），必须走 `.predict` 双契约
（同 `match_engine.calibrate_t1_with_ce`）。首跑冒烟因此 CE 全记 0.0（异常被
逐员工吞掉），已修正重跑——**任何新 CE 消费方一律复用双契约**。
