## §一 Day 1-2 诊断（预注册四问）

诊断**不改打分主链路**，只做只读回放与归因。泄漏级别记 **L0**（只读）/L1（模拟判定）。

### 问题 1：JD—证据可证性复核（不看任何模型分数）

对现有 10 岗（旧 5 岗 + 新 5 岗）逐岗做人工复核，每岗回答三条：

1. 金标员工是否被**记录本身**支持为合格（而非"根据人物背景知道他应该合格"）；
2. 是否存在同样合格、甚至更合格的**其他**员工；
3. 失败案例属哪一类：**检索失败**（证据在但找不到）／**证据缺失**（记录里根本没有）／**要求漂移**（JD 要求与金标证据不是同一命题，如"边缘计算网关"≠"MCU/STM32/ARM"）。

产出：可证性复核表（岗 × 员工 × 三问），任何标签修订均保留原标签+理由+独立复核记录。

### 问题 2：全 50 人 CE 诊断（不让 T0 掩盖结果）

固定证据输入方式，对每个岗位跑全部 50 个 JD—员工对的 CE 独立评分，记录：

- 金标在 bi-encoder 阶段的 rank 与 Recall@10（CE 是否实际见到了金标——没进 Top-10 则 CE 无纠错机会）；
- CE 单独排名 vs 最终融合排名的差异；
- 正例（金标）与**经裁定**负例之间的分数排序与区间重叠（0.48–0.56 窄区间不直接等于无区分度）。

判定树（事前冻结，结果对号入座）：

| 观察结果 | 归因 | 行动 |
|---|---|---|
| 全量 CE 排名好，最终评分差 | T0 主导或融合标定问题 | 暂不训练 |
| 全量 CE 好，Top-10 CE 差 | 候选覆盖问题 | 扩大或取消小库截断 |
| 全文匹配差，片段匹配好 | 粒度/截断/信息稀释 | 转要求—证据片段化 |
| 片段级 CE 仍分不开已裁定正负例 | 模型能力/领域适配 | 才进入训练调查 |
| CE 判断合理但指定金标落后 | 多正确答案/金标可证性 | 回问题 1 |

### 问题 3：输入路径检查（排查清单，非断言有 bug）

逐条核验并留证：长履历是否被截断、区分性证据是否落在尾部；通用介绍/部门描述/360 评语是否淹没正文；query/document 编码方式是否符合 checkpoint 要求；pooling、归一化、缓存键；原始 cosine/CE logit 到最终分数之间是否存在不合理压缩或裁剪。

### 问题 4：blend 0.5 量纲检查

bi cosine 与 CE 输出不是同一可解释量纲，各占一半缺乏依据。检查融合前后排序是否被单一通道支配；融合分**不解释为资格成立概率**，标定只允许在开发集进行。

## §二 Day 3-5 实现（预注册评分骨架）

T2/T3 通道在此期间**暂冻结**，只动主链路。

### 2.1 要求抽取规则

- JD 拆为**少量原子要求**，必要项与加分项分开标注，权重 w_r 来自 JD 的必要性定义，**不得**根据"哪个员工应获胜"设置。
- 可离线辅助解析，但解析结果必须**人工核验并冻结**后方可进入评分。
- 聚合歧义处理规则（事前冻结）：形如 "MCU/STM32/ARM" 的斜杠枚举，默认按**上位概念+实例**处理（命中其一即满足，不机械计成三项）；JD 明确"同时具备"才按并列要求拆分；明确"或"才按任选处理。
- 抽取完成即冻结要求集 R 与权重表，冻结后修改 = 违规。

### 2.2 证据检索规则

- 员工记录按原始条目/项目切片，保留来源、原文位置、记录 ID。
- **原始记录始终可检索，不以标签抽取成功为前提**（防标签召回上限回灌）。
- 每要求 r 从每员工 c 用词法检索 + embedding 双通道召回候选证据，保留上限 k 条（k 初值 ≤3，冻结时定版）。
- CE 对候选证据逐对评分。成本预估 50×m×k 对（m=要求数），须批处理并实测延迟，延迟数据写入验收报告。

### 2.3 关系分类 g(r,e)（五类，事前冻结定义）

| 关系 | 定义 | 计分处理 |
|---|---|---|
| 等价表达 | 经核验的同义改写（IoT↔物联网） | 满足上下文条件后同档计分 |
| 有向支持 | e 是 r 的下位实例（完成 STM32 固件开发→有 MCU 固件开发经历） | 可支持，**禁止反向推导** |
| 仅相关 | 主题相邻但不蕴含能力（参与边缘计算网关→熟悉 STM32） | 仅作候选召回，不计成立 |
| 证据状态不同 | 计划/学习中 vs 已完成（计划学习 MCU ≠ 完成 MCU 项目） | 不同分 |
| 明确否定/冲突 | 记录明确说明未参与相关开发 | 单独标记，不被高相似度覆盖 |

- **不单独设"字面加成"**：等价改写不因未用原词而降档。字面匹配的价值是便于验证，不是天然更符合岗位。
- D2 密度分保留为**证据可信度修正**，但须核验"多源"是否真独立——同一项目被不同报表复制不得自动从 0.6 升到 1.0。

### 2.4 评分骨架

```
S(j,c) = 80 · [ Σ_{r∈R_j} w_r · v(r,c) / Σ_{r∈R_j} w_r ] + 10·B(c) + 10·P(c)
v(r,c) = max_{e∈E_c} g(r,e)
```

- 80+10+10 是**减少同时变动因素**的暂定值，不是理论最优权重；冻结时确认或调整一次，之后锁死。
- 每个岗位要求只有一个有上限的贡献；字面、同义、有向支持是同一要求的不同验证通道，不重复加分；同一事实重复出现不制造多个独立能力项。
- CE 高分只是相关性信号，不得直接解释为"该要求已成立"。
- 缺证 ≠ 确定不合格，也 ≠ 本人不具备能力；涉及必要条件时进入人工核验，不自动判负。

### 2.5 工作台输出（证据矩阵，必交付）

| 岗位要求 | 支持状态 | 证据 | 限制 |
|---|---|---|---|
| MCU 固件开发经历 | 已支持 | 项目记录及原文片段 | 仅证明经历，不证明专家级熟练度 |

每行可追溯到原始记录 ID 与原文片段——这是竞赛差异点：不只给相似度，还说明哪项要求被什么证据支持、哪里仍不知道。

## §三 Day 6-7 T3 修复（预注册）

闭合映射升级为：**离线可扩展、发布后冻结**的版本化映射。

流程：完整原始概念流 → 判定证据类型（可多标签：专业能力/行为/潜力代理）→ 查等价概念或经批准的有向映射（有→映射提议；无→待审队列，**不强行 argmax**）→ 人工核验 → 版本化发布 → 运行时固定查表，未覆盖项保留原文返回 `unknown`。

四条硬规则：

1. **T2/T3 不互斥**：允许有依据的多标签（"非职权影响力"可同时是行为与潜力代理）；同一事件不得在多层无上限重复加分。
2. **映射带证据条件**，不是词对词（"逆境反弹"的支持条件须含受挫背景+后续行动+恢复/改善结果；"抗压能力强"不直接等价）。
3. **cap 在路由后施加并记录损失**：保留输入概念数、未映射数、路由结果、被 cap 截断的概念及原因。可分维度预算，但**不得因已知那 9 个答案而专门开保留规则**。
4. **360 通道防重复**：同一段评语不得在 T2 满分后又换名在 T3 再得分。潜力输出声明为可观察行为的代理指标，不是人格诊断。

验收口径：batch2 T3 ≥4/9 保留为**开发集恢复目标**，但必须同时报告 TP/FP/FN/unknown/cap 丢失量——只设召回下限会鼓励过度贴标签。

## §四 Day 8 冻结清单 + Day 9-10 独立验收

冻结对象（全部定版并记录哈希）：模型与映射文件、评分公式与权重、要求集与解析规则、阈值、依赖版本、种子、批处理配置、输入顺序。同分排序以员工 ID 等稳定键处理。

**验收口径（事前冻结）：**

1. **主指标 nDCG@5**（若分级相关性可补齐；允许多个正确答案，不惩罚合理替代者），同时报告指定金标 Top-5 命中作为连续性指标。
2. **margin 不作跨结构比较的唯一主指标**——公式变化后"多 3 分 margin"未必同义。优先比较同一批岗位上的配对排序指标变化，保留逐岗结果。新 5 岗负 margin 是警报；pooled CI 跨零 = 未建立稳定正优势，不等于证明所有场景劣于基线。
3. **统计单位是岗位，不是运行次数**：确定性系统三次运行只验证复现，样本量不 ×3；同一岗位的多个改写按岗位分组，不当独立考题。
4. **负例双层**：保留简单负例（零交集构造），新增**经独立裁定的难负例**（词面很像但必要条件无支持者）。"招聘主管压过 HR 专家"类合理候选未经裁定不得纳入负例。
5. **阈值重标定只在开发阶段进行**：原 0.35/0.40 不因分数仍显示 [0,1] 而自动有效；标定完再冻结，看了新考卷后不得调整。
6. 验收同时提交：确定性测试（同输入同输出）、证据链展示抽查、延迟实测。
