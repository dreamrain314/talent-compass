## 一、对方产品全貌（页面 13 节逐条实录）

**同一道题**：九洲集团 21,000 名员工（我们开题报告同为九洲集团场景），信息散在 14 个来源系统（Excel / PDF / 纸质档案 / 业务系统 / 协作记录），汇聚为 **4,765 条证据**，连成数字画像图谱。队名：九州-AI人才星图队（成员：郑健，单人队伍）；赛道：2026 AI 先锋未来人才大赛 · 效率先锋赛道 · AI 人才匹配 × 飞书业务闭环。

**四环闭环叙事**：看明白（数字画像）→ 找出来（语义匹配）→ 信得过（可核验可申诉）→ 用得久（反馈回流）。

### 技术核心（§09，与我们的卡点直接相关）

- **三层向量栈**，按成本与效果分工：
  - L1 `hashngram-v3`：基础层，零成本（字面 hash + n-gram 检索）
  - L2 火山远程 embedding：居中层（火山方舟 API）
  - L3 **118M 微调 e5**：主力层，本地小模型，不产生模型 API token 费；**1 次语义重排 / 请求**
- 微调数据/评测：**TalentCLEF 2025 中文集 Validation**（CLEF 公开基准，Task A 多语言职位匹配含中文轨道，MAP 指标，语料在 Zenodo record 15038364）
- 实测：MAP **0.496 → 0.523**（微调 + 语义重排，同一 validation 前后对照）
- 评测纪律：固定 validation 切分、MAP 指标、同一脚本重跑复核；**只报同一切分的前后提升，不与公开 test 名次横向比较**（跨切分名次比较无效）

### 盲测协议（§05，他们的"效果"验收方式）

1. 资深 HR 独立预埋最合适人选（金标）
2. 系统盲搜（全程不知道标准答案）
3. 命中验证——页面上宣称金标盲测 **5/5 全部命中**

### 招牌案例（§06）

简历写「单片机嵌入式开发」，岗位要「雷达微多普勒分析」——关键词**零重合**，按老办法第一轮就被筛掉。系统通过底层能力相通（杂波抑制 × 滤波器设计 × 杂波建模 × 频域成形 × 时频分析 → 微多普勒特征提取）找回，**推荐名单第 1 名**。这就是"搜不到，不代表不合适"的实证。

### 评分与可信层（§08）

- **固定公式 · 百分制 · 零 LLM 评分**：直接技能 50 / 技能迁移 20 / 项目契合 20 / 证据契合 10 = 100
- "AI 管理解，公式管评分。人，保留最终决策权"
- 证据分层：<0.60 驳回 · 0.60–0.85 待审 · ≥0.85 自动通过；最终用人由人审批
- 理由可核验：每条推荐理由**可点回原始证据**，当场核验
- 反事实校验：改变一项匹配条件，重新检查推荐是否成立
- 合规叙事：围绕个保法第二十四条"透明、公平"要求

### 工程指标（§07）

- 匹配引擎 **0.63 秒**给出 Top-5（对比：人工筛一遍需数周）
- **连跑两次逐位一致**（结果稳定可复现）
- 编队功能：按团队组合看人（不只看单个候选人）

### 飞书闭环（§10）

HR 自然语言提需求 → 推荐卡片推回飞书 → 采纳/驳回点击 → 审批确认 → **21 秒回传**并完成状态闭环。反馈写入**多维表格 + 豆包工作伙伴知识库**，成为**离线调优样本**；异常线索由人复核。"每一次选择，都成为下一次选择的养料。"

### 业务价值与可复制性（§11-12）

- 试点测算：研发人员 1000 名、内部岗位需求 80 个/年、内部填补率 +15% → 减少 12 次外部招聘 × 单岗 8–15 万 = **年化 96–180 万元**
- **6 天完成可运行原型**；流程全部跑在飞书标准能力上（审批、多维表格、豆包知识库、交互卡片），算法服务轻量接入
- 明确承认"不把可推广性说成零定制"——真正可复制的是标准流程、接口契约和资产清单

## 二、差距分析：我们卡住的地方，他们怎么"解决"的

### 核心判断：他们不是解决了我们的召回率问题，而是用架构绕开了这个问题存在的土壤

我们的卡点（2026-09-04 归因回放，`docs/plan_t1_optimization.md`）：
- T1 recall@GT 实测 25–37.5%（目标 ≥60%）
- **87% 的 miss 在抽取层**（LLM 单次没抽出 concept），13% 在匹配层
- 决定性事实：6-run concept 并集可命中 7/8 GT（87.5%）——能力不是瓶颈，**单次抽取的非确定性才是**
- 后续 S2 实验把参照臂推到 C_rGT 68.3%，但 JZ0003 人工审计暴露三层故障（截断残词「主动学」→ LLM 补全升格 → rerank conf 0.575 次近邻错映射「自驱力」）——"召回率≠效果好"首个实证

他们的架构里，这类 miss **结构性不存在**，原因有三层：

1. **检索不依赖"单次 LLM 抽取"**。我们把"员工证据 → LLM 抽 concept → 映射到标准标签库"作为召回的关键路径，LLM 一次没抽出 = 永久 miss。他们的"找出来"是证据与岗位要求**直接进向量空间做语义匹配**（L1 字面 + L2/L3 语义三层栈），LLM 抽取不是召回的前置闸门。单片机 vs 微多普勒案例正是证明：不需要抽出任何"正确标签词"，embedding 空间自己把能力内核拉近。
2. **监督微调替代 prompt 工程**。我们当时评估 S5（SetFit 微调嵌入）后否决，理由是"归因显示匹配层不是主瓶颈 → 打击面错位"——这个推理**在我们的架构内是对的**，但它是架构相对的：他们把瓶颈搬到匹配层后，微调 118M e5 正是主杠杆（MAP +0.027）。教训：否决一个方案时要标注它隐含的架构前提。
3. **验收指标换了坐标系**。我们的 recall@GT 是"标签级中间指标"（8 个 GT 标签 ±1 命中 = ±12.5pp，被迫 3-run 均值）；他们的金标**盲测**（HR 预埋人选、系统盲搜、Top-5 命中 5/5）是"端到端任务结果指标"——这恰恰是用户 2026-09-10 拍板的方向（召回率≠效果好 → 抽出正确的能力 → 扩 GT 样本集），他们把它落成了产品级验收协议。

### 逐项对照表

| 维度 | 我们（Talent Compass） | 他们（TalentAtlas） | 判读 |
|------|----------------------|---------------------|------|
| 匹配范式 | LLM 抽标签 → 标准标签库映射（标签槽位制） | 证据 ↔ 岗位直接向量语义匹配 | **决定性差距**：他们绕开了"人写的词对不上词表的词" |
| 召回卡点 | 抽取层 87% miss，S3 多遍并集可到 87.5% 但成本×3 | 检索不依赖单次抽取，该类 miss 结构性消失 | 他们赢在架构选型，不是算法更优 |
| 嵌入模型 | bge-small-zh（fastembed ONNX，未微调） | 118M e5 **在 TalentCLEF 2025 中文集微调** + 1 次语义重排/请求 | 微调+重排是我们 S5 曾否决的路线，在他们架构里成立 |
| 评分 | LLM/rerank 置信参与（JZ0003 三层故障） | **固定公式百分制、零 LLM 评分** + 置信分层（<0.60 驳回） | 他们用确定性公式杀掉了我们审计发现的噪声类问题 |
| 可信/审计 | Agent⑤ 质量审计 + 证据锚点追溯 + 反事实解释（设计里有） | 理由点回原始证据 + 置信分层 + 反事实校验 + 人保留终审 | **理念同源**（我们开题报告早就有），他们展示得更产品化 |
| 评测口径 | recall@GT（标签级，样本 8–16，需 3-run 均值） | 金标盲测 5/5 + 固定 validation MAP + 同脚本重跑 | 端到端结果指标 > 中间指标；且纪律严（不跨切分比名次） |
| 数据飞轮 | "扩 GT 样本集"是人工活（5 员工 35 标签起步） | 每次采纳/驳回自动回写为离线调优样本 | 他们把 GT 生产变成了产品内置流程 |
| 确定性 | 6-run concept 36–50 个 vs 单 run ~15，需并集补救 | 连跑两次逐位一致，0.63s Top-5 | 确定性是可信叙事的地基 |
| 交付形态 | Python/Streamlit 单机 demo（489 测试） | 飞书原生闭环（多维表格+卡片+审批+豆包知识库），6 天原型 | 赛道就是"飞书业务闭环"——评委看得见业务跑起来 |
| 独有优势 | 五层金字塔（H0-H1-T0-T1-T2-T3）、360 综合公式（时间衰减/区分度/置信度）、心理学理论底子、T2/T3 深层标签 | 编队功能（按团队组合看人）、个保法合规叙事、业务价值测算 | 我们的分层深度和理论底子是对方页面没有的；他们的业务化包装是我们缺的 |

一句话总结：**我们在"把人翻译成词表"这件事上做到了工程极限（并集、兜底、审计），他们证明了这条路可以不走到头——直接在语义空间里配对，把 LLM 退到"理解与解释"的位置，把评分交给公式，把验收交给盲测。**

## 三、复现路线图（后期执行参考）

### 第一步：复刻检索核心（三层向量栈）

1. **数据**：TalentCLEF 2025 语料（Zenodo record 15038364；Task A 多语言职位匹配，中文轨道，MAP 评测）。固定 validation 切分，只做同一切分前后对照。
2. **L3 主力层**：`intfloat/multilingual-e5-base` 或 `erwin-ml/e5-base-zh`（~118M）用 sentence-transformers 微调（对比学习/CoSENT）。训练环境需 torch（我们 fastembed ONNX 不可训练，与当年 S5 评估一致）。
3. **重排层**：本地已有 `D:\workplace\bge-reranker-v2-m3\`（4.3G）——对应他们"1 次语义重排/请求"，零新增成本。
4. **L1/L2**：L1 字面 hash+n-gram（BM25 即可等价起步）；L2 火山方舟 doubao embedding API（远程兜底）。L1→L2→L3 分层是成本设计，复现时可先 L1+L3 两层跑通。

### 第二步：画像与证据层

- 沿用我们已有的多源汇聚与**证据锚点追溯**（这点我们本来就有，是他们"理由可核验"的同款）
- 员工侧不追求标签全抽准：证据文本切片入向量库，标签只作展示层聚类，不承担召回职责

### 第三步：评分公式与可信层

- 复刻固定公式：直接技能 50 / 技能迁移 20 / 项目契合 20 / 证据契合 10（权重可调，关键是**零 LLM 评分**）
- 置信分层 <0.60 驳回 / 0.60–0.85 待审 / ≥0.85 自动通过 + 反事实校验（改一项条件重查）

### 第四步：盲测台（验收协议）

- 直接改造我们已有的资产：`data/audit/evidence_audit_20260910_reviewed.csv`（40 条人工核验）+ codebook_gt_v0 → 升级为"HR 预埋金标 → 系统盲搜 → Top-5 命中率"的盲测脚本
- 指标：金标命中率（端到端）为主，TalentCLEF validation MAP 为辅（回归测试）

### 第五步：飞书闭环（若要复刻交付形态）

- 多维表格（画像+证据+反馈回流）+ 交互卡片（推荐理由+可点回证据）+ 审批流 + 豆包/知识库沉淀调优样本
- 算法服务轻量接入（FastAPI 包住三层栈即可，端口按 AGENTS.md 用 3002/8082）

### 风险与注意

- MAP 0.496→0.523 的绝对值不高，他们的竞争力主要在**闭环叙事+验收协议+合规**，不在模型精度——复现时不要在模型上调过头
- 我们的五层金字塔/360 公式/T2-T3 深度可以保留为差异化，叠加他们的检索与验收框架（不必二选一）
- 微调需 GPU/torch 环境；TalentCLEF 中文集规模需下载后确认
