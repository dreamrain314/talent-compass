## 0. 引用约定（幽灵标签防线）

- 本文件中，全角弯引号与反引号**仅允许**包裹标准标签名：即 standard_label_library_v1.json 的 62 个 name ∪ t0_registries.json 的 59 个 name（corpus 条目口径 121；重名 3 条去重后 name 池 118）。
- 证据短语（如 **网络技术**、**边缘网关开发**、**边缘计算网关**）与一般关键词（如 **MQTT**、**MCU**、**SPC**）一律用粗体或明文，**禁止**用上述两种定界符包裹——这是第五节负向断言可机械执行的载体约定。
- 标签名池是封闭集合：GT 与抽取输出中的 standard_label 必须逐字命中该池；concept 亦不得使用池外短语冒充标签（见 B6）。

## 一、标注总则

1. **标注对象**：员工 × 标签 的能力画像 ground truth，结构对齐 data/experiment/ground_truth_5.json（每条含 label / category / tier / evidence）。
2. **证据分级（核心规则，对齐 GT 复核既有裁定与 _build_system_prompt 现行文案）**：
   - **一级证据**：项目摘要、绩效摘要、岗位序列（job_sequence）。单独一条一级证据即可支撑一个标签。
   - **佐证证据**：证书、培训课程。**孤证不抽**——须与项目或绩效（或岗位序列）相互印证方可计入。
   - GT 复核既有裁定实录（progress.md 2026-09-10）：
     - 拒绝案例：JZ0003 培训字段挖出的 **ITIL**/**Redis** 类标签被 GT 否决——理由是『仅培训无项目证据』。注意 **ITIL** 与 `Redis` 本身是 registry 合法名，被否决的是其**证据等级**，不是名字合法性。
     - 接受案例：JZ0001 岗位序列（质量工程师）+ 培训（质量管理体系 ISO9001，score 91）互证 → `质量工程` 计入。
3. **evidence/snippet 规则**：必须是原文精确子串（≤20 字），不得改写、拼接跨句片段。
4. **忠实原文**：不添加原文中没有的信息，不做推断；能力等级（sfia_level/ability_score）只在有证据支撑时评定。
5. **通道分工**：T1 只看专业能力证据（项目/绩效/证书里的技术技能），T2 只看行为表现（360 评价），T3 只看潜质信号；三通道互不挪用证据。

## 二、易混对判别

每对给出：判据（关键词/证据模式级，可直接执行）、正例、反例、须防的错误倾向。员工 ID 与证据均取自 ground_truth_5.json 实证。

### 2.1 嵌入式开发

- **标签身份**：`嵌入式开发`（T1 skill；TOOL_REGISTRY 同名条目，别名 嵌入式系统/MCU/单片机/STM32/ARM——别名不是 name，粗体呈现）。
- **判为 `嵌入式开发` 的证据模式**：
  - P1（固件/驱动词根）：证据同时含硬件平台词根（**MCU**、**单片机**、**STM32**、**ARM**、**RTOS**、**固件**、**驱动开发**、**FPGA**）与低层语言词根（**C**/**C++**）。
  - P2（边缘网关模式，序5 残留问题的靶点）：项目名含 **边缘计算网关**/**边缘网关**/**智能网关**，且 tools/职责含 **嵌入式/C++/Linux/MQTT** → 判 `嵌入式开发`。正例：JZ0004 项目『边缘计算网关开发（核心开发，tools含嵌入式/C++/Linux/MQTT）』。
  - P3（平台协同）：FPGA/ARM 平台软硬件协同设计与调试 → `嵌入式开发`，与 `FPGA开发` 可并存（不互斥）。
- **不判的反例**：
  - N1：纯网络设备运维/组网证据（**路由器**/**交换机**配置、组网实施、网络调试）→ 不判 `嵌入式开发`。去向：组网/协议设计 → `通信系统`；设备与系统运维保障 → `运维工程`。
  - N2：仅服务端开发证据（**Java**/**Linux** 服务端业务系统，无边缘侧硬件词根）→ 只判 `Java开发` 等服务端标签。
- **须防的错误倾向（实测残留）**：LLM 把边缘计算网关证据**语义归并进 Java/Linux 主干概念**——序5 中 JZ0004 三轮 concepts 零嵌入式词根，`嵌入式开发` 0/3。GT 裁定：同一员工 `Java开发` 与 `嵌入式开发` **并存**（JZ0004 GT 两者皆有），抽取端必须按 P2 强制分立成两条，不得归并。

### 2.2 网络技术

- ⚠️ **事实约束：网络技术不是标签库标签**（planner grep 实证 + 第五节负向断言）。它只能以**证据短语**身份出现在 text_snippet/evidence 原文里，**禁止**作为标签、concept 或 standard_label 输出。
- **证据短语 → 标签 的分流判据**（证据中出现 **网络技术** 字样时）：
  - D1：**TCP/IP**、**路由交换**、**组网**、**无线/WIFI**、通信协议栈 → `通信系统`。
  - D2：**渗透测试**、**防火墙**、**安全审计**、攻防 → `网络安全`。
  - D3：纯设备/网络运维保障（监控、故障处置）→ `运维工程`。
  - D4：行业语境（通信设备/路由器/交换机制造商业务）→ domain `网通产品`；**IoT**/传感器网络语境 → domain `物联网`。
  - D5：边缘设备侧协议（**MQTT**/**Modbus**）+ 嵌入式词根 → 走 2.1 判 `嵌入式开发`。
- **反例**：把 网络技术 当作 concept 或 standard_label 输出 = 幽灵标签，GT 复核直接否决。

### 2.3 边缘网关开发

- ⚠️ **事实约束：边缘网关开发/边缘计算网关开发不是标签库标签**（同上，grep 实证 + 负向断言）。处置同 2.2：仅作证据短语，禁作标签。
- **证据短语 → 标签 的分流判据**：
  - E1（主判据）：**边缘计算网关开发** + **嵌入式/C++/Linux/MQTT** 证据 → `嵌入式开发`。正例：JZ0004（GT 实证在案）。
  - E2：证据主体是网关上运行的服务端应用（**Java**/**Go** 业务服务，无硬件/固件词根）→ 按服务端语言判 `Java开发` 等。
  - E3：证据主体是网关组网、部署、运维 → `运维工程` 或 domain `物联网`/`网通产品`。
- **须防的错误倾向**：归并进 Java/Linux 主干（序5 残留，同 2.1）。rerank rationale 引用本节时必须显式列出边缘侧词根清单（嵌入式/C++/Linux/MQTT），不得只引用主干语言词根。

### 2.4 质量工程

- **标签身份**：`质量工程`（T1 skill；关键词 QE/PQA/FQA/IQE/CQE/SQE/质量管控/不良分析/抽样检验/SPC）。
- **判为 `质量工程`**：来料/过程/成品质量管控、质量工具运用（**SPC**、**8D**、**FMEA**、不良分析、抽样检验）的项目或绩效证据；质量岗岗位序列。
- **判为 `体系工程`（近邻区分）**：证据主体是 **ISO9001/IATF16949/QC080000** 体系的建立、维护、内审、外审应对。两标签不互斥：既有体系运行又有质量改进工具运用时可并存。
- **证书联动（与 2.5、第一节证据分级衔接）**：ISO9001 证书/培训**孤证不判** `质量工程`；须与岗位序列或质量项目互证。正例：JZ0001（岗位 质量工程师 + 培训 质量管理体系 ISO9001 score 91 → `质量工程` 计入，另 360 证据支撑 T2 `质量导向`——两标签分属不同通道，不可互相替代）。
- **须防的错误倾向**：序5 实测——概念层抽出『质量管理体系』后 rerank 最近邻命中 `ISO9001` 工具条目（conf 0.96）而非 `质量工程`，造成证书→能力映射鸿沟；GT 侧对应规则即本节互证要求 + 2.5 的映射规则。

### 2.5 证书（证书→能力映射规则）

- **R1（总规则）**：证书须映射到**能力标签**，禁止照抄证书名作为 standard_label 或 concept。
- **正例 1**：ISO9001 认证/培训 + 质量岗位或质量项目互证 → `质量工程`。与 _build_system_prompt 现行文案逐句对齐：『证书须映射到能力标签而非照抄证书名（如 ISO9001 认证佐证质量工程能力）』。
- **反例 1（照抄证书名）**：standard_label 输出 `ISO9001` 充当能力标签——序5 实测 _FEWSHOT_BANK[5] 的 ISO9001→ISO9001 样例与文案矛盾，是 JZ0001 `质量工程` 0/3 的主因；序5b 修正为 ISO9001→`质量工程` 后救回 2/3。
- **反例 2（证书名当 concept）**：concept 填 **质量管理体系ISO9001** 之类原文长短语，违反『concept 必须是 ≤8 字抽象能力名、禁止照抄原文片段』的现行规则。
- **边界**：证书名本身可作为**知识体系证据**归档（如 `ISO9001`、`六西格玛`、`ITIL` 是 KNOWLEDGE/TOOL registry 合法名，可作为 T1 knowledge/tool 类标签在**互证成立时**计入），但其进入画像的通道是『佐证 + 映射到能力标签』，不是照抄。

### 2.6 主动学习 vs 自驱力 vs 成长型思维（2026-09-12 首批人工审计裁定新增）

- **判别条件**：「主动承担责任 / 发挥关键作用 / 自发推进 / 兜底」词根 → `自驱力`（行为主动性）；「主动学习 / 自学 / 钻研新技术 / 快速掌握 / 跨域学习 / 技术视野开阔」词根 → `成长型思维`（学习行为）。「主动」单字词根同时服务两者，**不得**仅凭「主动」就映射任一标签。
- **实证案例（JZ0003 孟华，2026-09-12 用户人工审计否决）**：360 评价原文含「主动承担责任…主动学（截断残词）」，抽取层产出 concept「主动学习」→ rerank 以 conf 0.575 映射 `自驱力`，8/16 run 全部 in_gt=True 算 TP——**次近邻侥幸命中**：证据无学习语义，且按 JZ0001 先例（『360: 主动学习、技术视野开阔』→`成长型思维`）该 concept 若成立应归 `成长型思维`。该案例成为「召回率≠效果好」的首个实锤。
- **残词禁令**：上游摘要被截断产生的残词（如「主动学」）不得作为 concept 抽取依据；抽取侧见到疑似残词应丢弃或标注低置信，不得补全升格。连带 backlog：phase1 `text_summaries.evaluation_summary` 存在生成期截断（Agent① 360 汇总质量问题，待排查 summary 生成 max_tokens）。
- **审计工具联动**：gen_evidence_audit.py 已修（截断容错匹配 + 兜底优先 GT 证据关键词单元）——修前该行证据列误显绩效摘要，误导首轮人工核验；教训入 §0 幽灵标签防线同类：「给核验人看的证据必须定位到 concept 真实来源字段」。

### 2.7 五类错误模式（2026-10-21 用户复核 gt5 证据审计 40 行新增，标注前必读）

用户复核推翻 9 行 / 查实 9 行（审计兜底缺陷），归纳出草稿标注的五类系统性错误。**每条标签落稿前逐类自查**：

1. **负向证据（领域匹配但绩效不佳）**：证据只证「做过」未证「达标」（如「工业大数据分析中部分节点延迟」不能支撑「数据分析」标签）。判别：证据含负向结果词（延迟/返工/不稳定/事故/整改）→ 不标。引擎侧护栏：`config.T0_NEGATIVE_MARKERS`（含负向标记的记录不进 T0 命中）。
2. **概念与证据错位**：证据支撑的是另一个能力（如「布置任务清晰、有主见能推动决策」支撑决策/推动力而非「资源整合」；leader/负责人/基层管理 支撑「团队管理/领导力」而非「团队协作」）。判别：把证据关键词与标签的 tier+category 对表，维度对不上不标。
3. **概念推断过度**：证据是结果/行为，概念却推成特质（如「B→C→A 翻盘」是绩效结果，推不出「成长型思维」——后者需要直面挫折主动调整的直接证据；「主动承担责任」只证担责，推不出「主动学习」）。判别：问「证据里有没有该特质的**行为过程**，而不只是结果」。
4. **低置信度+证据截断**：match_confidence < 0.3 且原文截断于关键词中途（如 0.1961 截断于「主动」）→ 人工回查原始记录，禁直接采信。
5. **兜底原文缺失**：审计行兜底原文为绩效摘要而目标概念实际在 360/项目/培训中 → 审计工具缺陷（gen_evidence_audit 兜底优先级），不代表标签错。处置：回查原始记录确认存在性（2026-10-21 排查 9/9 存在，全部升级支持）。

## 五、幽灵标签负向断言（自动检查）

- **检查定义**：提取本文件中全部反引号与全角弯引号包裹的候选名，断言候选集合 ⊆ 标签名池（standard_label_library_v1.json 62 名 ∪ t0_registries.json 59 名）。定界符字符在源码中以转义形式给出，保证本文件自身可被同一脚本检查。
- **通过标准**：集合差为空；**网络技术** 与 **边缘网关开发** 不得出现在候选集合中（它们只以粗体证据短语身份出现，永不加定界符）。
- **复现命令**（项目根执行）：

```python
import json, re
md = open('docs/codebook_gt_v0.md', encoding='utf-8').read()
cands = set(re.findall(chr(96) + '([^' + chr(96) + r'\n]+)' + chr(96), md))
cands |= set(re.findall('\\u300c([^\\u300d\\n]+)\\u300d', md))
lib = json.load(open('data/standard_label_library_v1.json', encoding='utf-8'))
reg = json.load(open('data/t0_registries.json', encoding='utf-8'))
pool = {it['name'] for v in lib['labels'].values() for it in v}
pool |= {it['name'] for v in reg.values() for it in v}
ghost = cands - pool
assert not ghost, sorted(ghost)
print('PASS', len(cands), 'candidates ⊆', len(pool), 'names')
```
